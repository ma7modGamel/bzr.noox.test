# Localization audit report

Audit date: 2026-10-11. These findings distinguish implemented corrections from device/release checks still outstanding. Existing unrelated work in this heavily modified checkout was retained; no production deployment was performed.

| File / module | Problem and root cause | Severity | Correction | Evidence |
| --- | --- | --- | --- | --- |
| `androidapp/.../network/BremoHttp.kt`, `iosapp/Core/.../APIClient.swift` | API calls did not transmit the app resource language; server-controlled labels stayed Arabic in an English UI | Critical | Shared clients send current supported `Accept-Language`; cached Android services evaluate it per request | Android network and Swift transport tests; live English catalog/config HTTP 200 |
| `app/Http/Middleware/ResolveLocale.php`, `bootstrap/app.php` | Backend messages/enums had no consistent locale boundary; validation and errors could use framework English or Arabic defaults | High | Supported locale negotiation, user fallback, request cleanup, localized error envelope and language headers, including unknown routes and unexpected failures | `LocalizationTest`; full PHP suite |
| `ConfigController`, business enums | Budget materials, pricing, timing, cancellation, payout and other choices returned hardcoded Arabic labels | Critical | Bilingual enum/template labels; stable business codes unchanged | Same-request ar/en contract tests; live materials labels checked in both languages |
| `Localization.php`, catalog/geography/support models and Filament forms | System service names and managed reasons had only one database field | High | Nullable English fields, launch-label source fingerprints, explicit 409 for missing managed translation; geographic proper names preserved | Seeded catalog and administrator-translation tests; live eight-category English catalog contains no Arabic |
| `ReferenceController`, `ProviderResource`, `ProviderProfileController`, `OrderResource`, `ProviderOfferResource`, `ConversationController`, `AddressController` | Localized references could be bypassed in nested resources/profile/conversation payloads | High | Localized category/problem/reason fields and necessary English eager-load columns | Backend suite exercises resource consumers; catalog contract tests protect leakage |

The audit is broader than the four defect descriptions: all shared screens/components and API route entries are inventoried. Catalog scans and fixture layouts cannot establish end-to-end rendered coverage for every live state. Do not treat the implemented corrections as final mobile release acceptance until the pending checks in `risks-acceptance.md` are completed.
