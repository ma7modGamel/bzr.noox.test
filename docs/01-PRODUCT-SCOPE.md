# 01 — نطاق المنتج

## ما يفعله المنتج
1. إنشاء طلب خدمة من ثلاث خطوات، مع وسائط (صور/فيديو/صوت).
2. توزيع الطلب على الفنيين المؤهلين (08)، أو تعيينه يدويًا من الإدارة في وضع الموظفين (39).
3. استقبال عروض ومقارنتها واختيار فني — **معطّل بمفتاح CFG-090 في المرحلة الأولى** (39).
4. تتبع الزيارة: تأكيد، في الطريق (خريطة + وقت وصول)، وصل، تنفيذ.
5. مسار "المعاينة أولًا" داخل نفس الطلب (11)، وهو المسار الوحيد في المرحلة الأولى وبرسوم صفرية (CFG-091).
6. مقترحات السعر بعد القبول: عرض تنفيذ، خامات، أعمال إضافية (12).
7. الإنهاء والدفع (نقدي/فوري) والتأكيد والتقييم المتبادل (14، 19).
8. النزاعات والبلاغات، وحلها من الإدارة.
9. تسجيل الفنيين وتوثيقهم يدويًا (15).
10. متابعة عمولات المنصة ومستحقات الفنيين بالحد الأدنى (19 §التسويات).
11. لوحة تشغيل للإدارة (16).

## ما لا يفعله المنتج (مستبعد صراحة)
| المستبعد | السبب / البديل |
|---|---|
| محاسبة عامة، دفاتر قيود، ضرائب، فواتير رسمية | خارج النطاق؛ النظام يحفظ مبالغ الطلبات وسجلات التحويل فقط |
| محفظة للعميل أو رصيد مخزن | DEC-011 |
| مخزون أو مشتريات خامات | الخامات مبلغ في مقترح سعر فقط (DEC-007) |
| شركات وفرق فنيين | DEC-001 (قابل للإضافة لاحقًا، 36) |
| حجز فني بعينه مباشرة | DEC-034 |
| طلبات الطوارئ | DEC-012 (لاحقًا) |
| رسوم إلغاء أو غرامات | DEC-016 |
| تفاوض رسمي على السعر | DEC-014 |
| أكثر من وضع تشغيل في نفس اللحظة | الوضع على مستوى المنصة لا المدينة ولا الفئة (BR-006؛ التوسعة في 36) |
| رسائل SMS | DEC-025 |
| إخفاء أرقام عبر مزود اتصالات | DEC-013 |
| CRM، حملات تسويق، كوبونات، ولاء | غير مطلوب للتشغيل |
| خدمات مصغرة (Microservices)، Event sourcing، Kafka | 30-SYSTEM-ARCHITECTURE |
