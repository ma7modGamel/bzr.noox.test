# 28 — نموذج الكيانات

تصنيف الحقول: **CORE** لازم · **OPT** اختياري · **FUTURE** لا يُنفذ الآن (مذكور لتوضيح اتجاه التطور فقط).

## الوحدة: الهوية
### User — المستخدم (عميل، وقد يكون فنيًا)
- CORE: الاسم، البريد (فريد)، `email_verified_at`، كلمة المرور، الهاتف، الحالة (ACTIVE/BLOCKED)، سبب الحظر.
- OPT: الصورة. محسوب: متوسط تقييمه كعميل وعددها.
- العلاقات: 1–N عناوين، طلبات، أجهزة؛ 1–0..1 ملف فني.
- الثوابت: BR-001، BR-003.

### Admin — مستخدم الإدارة
- CORE: الاسم، البريد، كلمة المرور، الدور (`OPERATIONS` / `SUPER`)، مفعّل.

## الوحدة: الجغرافيا والكتالوج
- **City**: الاسم، مفعّلة، المنطقة الزمنية، المركز/نصف القطر (OPT). FUTURE: المحافظة.
- **Area**: المدينة، الاسم، مفعّلة، الترتيب. FUTURE: مضلع الحدود.
- **Category**: الاسم، الأيقونة، الترتيب، مفعّلة. N–N مع City (`city_categories`).
- **ProblemType**: الفئة، الاسم، `is_other`، الترتيب، مفعّل.

## الوحدة: العملاء
- **CustomerAddress**: المستخدم، التسمية، المدينة، المنطقة، النص، المبنى، الدور، الشقة، علامة مميزة، الإحداثيات، افتراضي. حذف ناعم.

## الوحدة: الفنيون
### ProviderProfile
- CORE: المستخدم (فريد)، الحالة، **صفة التعاقد** (`employment_type`: EMPLOYEE / INDEPENDENT — 39)، الخبرة، "متاح الآن"، `phone_verified_at`، بيانات المراجعة (من، متى، سبب الرفض/الإيقاف)، طريقة الاستلام + بياناتها (مشفرة).
- OPT: النبذة.
- محسوب ومخزن للأداء: متوسطات التقييم الأربعة، عدد التقييمات، الخدمات المكتملة، سرعة الرد (تُحدث بمهمة).
- العلاقات: مستندات، فئات، تخصصات (أنواع مشاكل)، مناطق، معرض أعمال.
- الثوابت: التخصصات داخل الفئات المعتمدة؛ فئة ومنطقة واحدة على الأقل للتفعيل.
- FUTURE: `organization_id` لدعم الشركات لاحقًا (DEC-001).
- **ProviderDocument**: النوع (ID_FRONT / ID_BACK / SELFIE)، المسار الخاص.
- **PortfolioItem**: صورة، وصف قصير، ترتيب.

## الوحدة: الطلبات (قلب النظام)
### Order
- CORE: الرقم المعروض، **وضع التشغيل المثبت** (`operating_mode`: EMPLOYEE / MARKETPLACE — BR-009)، العميل، الفني (بعد التأكيد)، العرض المقبول (أو صف التعيين — BR-007)، **من عيّن ومتى** (وضع الموظفين)، المدينة، المنطقة، الفئة، نوع المشكلة، الوصف، **نسخة العنوان**، الموعد (`NOW`/`SCHEDULED` + الفترة)، طريقة التسعير، الخامات، الحالة، `offers_close_at`، `selection_deadline_at`، طريقة الدفع، حالة الدفع، نسبة العمولة المثبتة، المبالغ المثبتة (مصنعية، خامات، إجمالي، عمولة، مسترد)، أوقات المراحل، بيانات الإلغاء، `settlement_eligible_at`، نسخة الشروط، `version`.
- OPT: الميزانية، `republished_from_id`، نقطة الوصول.
- الثوابت: 10 كاملة؛ BR-040، BR-044، BR-060.
- **OrderMedia**: النوع (IMAGE/VIDEO/AUDIO)، المسار، المدة، الحجم.
- **Offer**: الطلب، الفني، **المصدر** (`source`: PROVIDER / ADMIN_ASSIGNMENT)، السعر، وقت الوصول، تُخصم؟، يشمل، ملاحظة، الحالة، `previous_offer_id`. الثوابت: BR-030..BR-034؛ صف `ADMIN_ASSIGNMENT` يُنشأ `ACCEPTED` بسعر 0 ولا تسري عليه (BR-007).
- **PriceProposal**: الطلب، الفني، النوع، المبلغ، السبب، الصورة، الحالة، `expires_at`، `decided_at`. الثوابت: BR-041..BR-043.
- **OrderEvent**: 24.
- **TrackingPoint**: الطلب، الإحداثيات، الوقت (مؤقت، BR-112).
- **ShareLink**: الطلب، الرمز، الانتهاء، الإلغاء.

## الوحدة: الدفع والتسويات
- **Payment**: الطلب، الطريقة، المبلغ، الحالة، البوابة، مرجع البوابة (فريد)، كود فوري، القناة، `paid_at`، من سجّل (للنقدي).
- **Refund**: الطلب، الدفعة، المبلغ + التقسيم، المرجع، السبب، المسؤول.
- **ProviderPayout**: الفني، المبلغ، الطريقة، المرجع، التاريخ، المسؤول.
- **ProviderRemittance**: الفني، المبلغ، الطريقة، المرجع، التاريخ، المسؤول.
- لا كيان "رصيد" ولا "قيد" (BR-062).

## الوحدة: التواصل والتقييم والدعم
- **Conversation** (طلب، فني، عميل، حالة) ← **Message** (المرسل، النص، هل حُجب، مرفق، مقروء).
- **Review** (طلب فريد، الأبعاد الثلاثة، نص، مخفي؟) · **CustomerRating** (طلب فريد، نجوم، مخفي؟).
- **Dispute** (الطلب، فاتحه، السبب، الوصف، بعد الإغلاق؟، الحالة، القرار، الملاحظة، من حسم) · **ProviderReport** (المبلِّغ، الفني، السبب، الحالة).

## الوحدة: الإشعارات والإعدادات
- **Notification** (جدول لارافيل القياسي) · **DeviceToken** (المستخدم، الرمز، المنصة، آخر استخدام).
- **Setting** (المفتاح، القيمة، من عدّل، متى) — يحمل CFG-090/091 وباقي مفاتيح 04 · **TermsVersion** (الرقم، النص، تاريخ السريان).

## ملكية البيانات
| الكيان | المالك | من يعدّل |
|---|---|---|
| Order (البيانات الأصلية) | العميل | العميل قبل أول عرض فقط |
| Order (الحالة) | النظام | عبر الإجراءات فقط |
| Offer | الفني (أو الإدارة في صف التعيين) | إنشاء/سحب فقط |
| PriceProposal | الفني ينشئ، العميل يقرر | — |
| Payment / Refund / Payout / Remittance | النظام / الإدارة | لا تعديل بعد الإنشاء؛ التصحيح بسجل جديد |
