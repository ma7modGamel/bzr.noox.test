# SCR-C26 — تفاصيل طلب سابق والإيصال

- النمط: C — تفاصيل.
- المرجع البصري: C08 و43 §4 (`SummaryCard` على أقسام).
- الطرف والوضع: العميل — السوق والموظفين.
- الدخول من: C25 في تبويب الطلبات السابقة · الخروج إلى: C24 عبر `rate` أو C27 عبر `open_dispute`.
- القواعد: BR-044، BR-050..BR-056، BR-090، BR-120، 14، 19، 23.
- الـ API: `GET /orders/{order}` و`GET /orders/{order}/proposals`.
- التخطيط (من أعلى لأسفل):
  1. `AppTopBar` بعنوان `order.details.title`.
  2. كارت حالة يعرض `status_label` ورقم الطلب.
  3. `SummaryCard` لبيانات الخدمة: الفئة، نوع المشكلة، المنطقة، والموعد.
  4. `ProviderHeader` للفني إن كان الطلب قد أُسند.
  5. قسم `receipt.title`: `SummaryCard` للمصنعية والخامات والإجمالي وطريقة الدفع وحالة الدفع من `amounts`، ومعرّف الإيصال هو رقم الطلب؛ لا يعاد حساب أي مبلغ في التطبيق.
  6. قسم المقترحات المقبولة إن وجدت، بالبيانات المعادة من `/proposals`.
  7. `PrimaryButton` للتقييم فقط مع `rate`، و`SecondaryButton` لفتح مشكلة فقط مع `open_dispute`.
- المتغيرات: CLOSED مدفوع/معفى، CANCELLED، EXPIRED، بلا فني، وبلا مقترحات. في CANCELLED يظهر سبب الإلغاء القادم من الخادم بدل الإيصال إن لم توجد مبالغ نهائية.
- السلوك: لا يُظهر الإيصال رقم الهاتف أو العنوان التفصيلي. جميع الأزرار من `available_actions` فقط. الضغط على التقييم يفتح C24، وعلى المشكلة يفتح C27.
- الحالات: تحميل / خطأ / طلب مكتمل نقدي / مكتمل إلكتروني / معفى / ملغي / منتهي / إجراء غير متاح.
- الأخطاء: `404` يعيد C25؛ خطأ الشبكة يعرض `ErrorState` مع إعادة المحاولة.
- fixtures: `design/fixtures/SCR-C26/cases.json`.
- أسئلة مفتوحة: لا يوجد.
