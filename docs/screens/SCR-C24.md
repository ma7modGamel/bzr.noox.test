# SCR-C24 — تقييم الفني

- النمط: A — نموذج.
- المرجع البصري: C07 (`RatingBars`) وC04 (الحقول) و43 §4.
- الطرف والوضع: العميل — السوق والموظفين.
- الدخول من: C09 أو C23 عبر `rate` · الخروج إلى: C26 بعد نجاح الحفظ.
- القواعد: BR-090..BR-092، 14.
- الـ API: `POST /orders/{order}/review`.
- التخطيط (DEC-076، Figma «قيّم الخدمة» 3002:4475، من أعلى لأسفل):
  1. `AppTopBar` بعنوان `rating.title`.
  2. شارة `rating.visit_done`.
  3. كارت الفني: الحرف الأول (B-16)، وعلامة التوثيق، والاسم، ونوع المشكلة، ثم `rating.question` باسمه الأول (أو `rating.heading` من غير اسم).
  4. كارت النجوم العامة و`rating.overall_hint`: الضغط على نجمة يحط البنود التلاتة بنفس القيمة، وبتظهر مختارة لما البنود التلاتة متساوية بس.
  5. كارت `rating.details`: صفوف `rating.quality` و`rating.punctuality` و`rating.conduct`، كل صف خمس نجوم.
  6. كارت `rating.tags` و`rating.optional`: خمس وسوم سريعة. **ثابت (DEC-074، B-04):** الوسوم المختارة بتتبعت في أول التعليق، وطول التعليق المحسوب بيشملها.
  7. كارت `rating.notes` فيه `TextAreaField`. زرار «إضافة صورة» مش ظاهر (B-04: `POST review` ما بيقبلش صور).
  8. في الشريط السفلي: `PrimaryButton` بالمفتاح `rating.submit` مع `rate`، وتحته `rating.after_submit`. سبب التعطيل (`rating.validation.required`) بيتقري لقارئ الشاشة بس.
- السلوك: كل بعد عدد صحيح 1..5؛ التعليق اختياري ويُقص طرفاه قبل الإرسال. التقييم لا يُعدل بعد نجاحه. لا تُستنتج نافذة السبعة أيام أو أهلية الطلب محليًا؛ يحددها `rate` وأخطاء الخادم.
- الحالات: تحميل / نموذج فارغ / نموذج صالح / أخطاء تحقق / إرسال / نجاح / نافذة منتهية أو تقييم سابق.
- الأخطاء: `VALIDATION_FAILED` يربط الخطأ بحقل البعد أو التعليق؛ `BUSINESS_RULE_VIOLATION` مع BR-090 يعرض سبب عدم الإتاحة بلا زر إرسال (انتهاء النافذة أو وجود تقييم سابق).
