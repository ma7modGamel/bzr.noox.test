# SCR-P09 — تفاصيل طلب متاح

- النمط: C — تفاصيل قراءة مع إجراء رئيسي.
- المرجع البصري: SCR-C05 بلا تعديل، و`ProviderHeader` بحجم متوسط لبيانات العميل المختصرة.
- الطرف والوضع: فني نشط في وضع السوق فقط؛ لا تُفتح الشاشة عندما `offers_enabled=false`.
- الدخول من: SCR-P08 عبر `open_available_requests` ثم اختيار طلب متاح، أو SCR-P11 عبر عرض مرتبط بطلب ما زال متاحًا · الخروج إلى: SCR-P10 عند `submit_offer`، أو SCR-P11 بعد `withdraw_offer`، أو SCR-C19 عند `chat`.
- القواعد: BR-022، BR-024، BR-030..034، BR-063؛ لا يظهر عنوان تفصيلي أو هاتف أو عروض فنيين آخرين قبل التأكيد.
- الـ API: `GET /provider/requests/{id}`؛ كل زر من `available_actions` فقط. وسائط الطلب وروابطها تأتي من الخادم، ولا تبني الواجهة مسارًا أو قائمة من عندها.
- التخطيط (من أعلى لأسفل):
  1. `AppTopBar` بعنوان `provider.market.request.title`.
  2. `ProviderHeader` باسم العميل المختصر وتقييمه فقط، بلا هاتف أو شارة فني.
  3. `Countdown` إلى `deadlines.offers_close_at` حين تكون النافذة مفتوحة.
  4. `SummaryCard` للفئة ونوع المشكلة والوصف.
  5. `MediaThumb` لكل وسيط ظاهر من الاستجابة، أو نص `provider.market.request.no_media` عند غياب الوسائط.
  6. `SummaryCard` للمنطقة والتوقيت وطريقة التسعير والميزانية ومسؤولية الخامات، مع إخفاء الصفوف التي يعيدها الخادم فارغة.
  7. `InfoBanner` لملخص العرض النشط الخاص بالفني إن وُجد؛ لا تظهر أي بيانات لعروض الآخرين.
  8. `PrimaryButton` لـ`submit_offer`، و`SecondaryButton` لـ`withdraw_offer` و`chat`، ولا يظهر أي منها إلا إذا ورد في `available_actions`.
- المتغيرات: تحميل؛ خطأ؛ طلب NOW تنفيذ بلا وسائط؛ طلب NOW معاينة بوسائط؛ طلب مجدول؛ عرض نشط خاص بالفني؛ نافذة منتهية أو طلب غير مؤهل بلا أفعال.
- الحالات: تحميل؛ محتوى؛ خطأ قابل لإعادة المحاولة؛ انتهاء/عدم إتاحة؛ سحب جارٍ؛ سحب ناجح.
- الأخطاء: `FEATURE_DISABLED` ← العودة إلى SCR-P08؛ `NOT_FOUND` أو BR-022/031 ← `provider.market.request.unavailable` ثم إعادة تحميل القائمة؛ خطأ الشبكة ← `error.body`.
