# SCR-C05 — مراجعة الطلب

- النمط: C — تفاصيل، الخطوة 5 من 5 (DEC-071).
- المرجع البصري: Figma «Primo App» 3002:1401. كارت لكل قسم (الخدمة، التفاصيل والمرفقات، العنوان، الموعد، الميزانية والخامات)، وفي كل كارت زر «تعديل» بيرجع لخطوته.
- الطرف والوضع: العميل، في وضعي الموظفين والسوق.
- الدخول من: SCR-C38 · الخروج إلى: SCR-C36 في وضع الموظفين، SCR-C06 في السوق، SCR-C34 للشروط، أو خطوات التعديل.
- القواعد: BR-008، BR-013..018، BR-019، BR-020، DEC-035، DEC-039، DEC-040.
- الـ API: `POST /orders` مع بيانات الخطوات والوسائط ونسخة الشروط من `/config`.
- التخطيط (من أعلى لأسفل):
  1. `AppTopBar` ثم `StepIndicator` 5/5.
  2. `ReviewCard` للخدمة ← SCR-C03، وللتفاصيل والوسائط ← SCR-C37.
  3. `ReviewCard` للعنوان والموعد ← SCR-C04، وللخامات والتسعير ← SCR-C38.
  4. السوق فقط: ملخص طريقة التسعير والميزانية.
  5. `CheckRow` معلوماتي بنص السوق `request.review.market.notice` أو الموظفين `request.review.staff.notice`.
  6. `CheckRow` إلزامي للموافقة؛ رابط `terms.link` يفتح SCR-C34.
  7. `PrimaryButton`: `request.publish.market` أو `request.publish.staff`.
- المتغيرات: موظفين/سوق؛ تنفيذ/معاينة؛ الآن/مجدول؛ مع/دون وسائط؛ الشروط مقبولة/غير مقبولة.
- الحالات: جاهز / تحميل النشر / خطأ تحقق / طلب مشابه قائم (تحذير غير مانع) / تجاوز الحد / عدم اتصال / نجاح.
- الإجراءات: النشر إنشاء مورد جديد وليس إجراء دورة حياة؛ بعد الاستجابة لا يُخمن المسار بل يستخدم `/config`: السوق إلى C06 والموظفين إلى C36.
- عقد 6ب: كل صفوف الملخص مشتقة من مسودة C03/C37/C04/C38 والكتالوج المحمّل، وطلب النشر يرسل معرّفي الفئة والمشكلة المختارين حرفيًا. إذا اختفى أي اختيار بعد تحديث الكتالوج يُمنع النشر ويعود خطأ تحقق، ولا توجد قيم افتراضية من أول عنصر.
