# SCR-C27 — فتح مشكلة ومتابعتها

- النمط: A — نموذج، ثم C — تفاصيل عند وجود ملف مفتوح أو محسوم.
- المرجع البصري: C04 للحقول، C20 لـ`RadioCard`، وC17 للوسائط.
- الطرف والوضع: العميل — السوق والموظفين.
- الدخول من: إجراء `open_dispute` في C09/C21/C23/C26 · الخروج إلى: C09 أو C26 بعد الإنشاء.
- القواعد: BR-120، BR-014 للصور، 16، T-22/T-23/T-24.
- الـ API: الأسباب من `GET /config` في `option_lists.dispute_reasons`؛ `GET /orders/{order}/disputes` للمتابعة؛ `POST /orders/{order}/disputes` بالسبب والوصف و`media_ids` بعد رفع الصور عبر `POST /media`.
- التخطيط: `AppTopBar` ← `ScreenHeading` ← `RadioCard` للأسباب التي يعيدها الخادم ← `TextAreaField` للوصف ← صور اختيارية عبر `MediaThumb` ← `PrimaryButton` من `open_dispute`. عند وجود ملف: كارت الحالة، السبب، الوصف، الصور، وقرار الإدارة إن حُسم.
- السلوك: الوصف إلزامي، والإنشاء ممنوع دون `open_dispute`. قبل الإغلاق يطبق T-22 ويعرض C09 في DISPUTED؛ بعد CLOSED يبقى الطلب CLOSED وتتوقف التسوية. ملف مفتوح واحد لكل طلب. لا تعدّل الشاشة الملف بعد إرساله.
- الحالات: تحميل / خطأ / نموذج فارغ / صالح / صور / إرسال / مفتوح / مقبول / مرفوض / مهلة منتهية / ملف قائم.
- الأخطاء: `BUSINESS_RULE_VIOLATION` مع BR-120 يعرض السبب ويعيد تحميل الطلب؛ `CONFLICT` يعيد التحميل؛ `VALIDATION_FAILED` يظهر عند الحقول.
- fixtures: `design/fixtures/SCR-C27/cases.json`.
- الأسباب الابتدائية المدخلة بالسيدر، مع إمكان تعديل التسمية والترتيب والتفعيل من الداشبورد: `WORK_QUALITY` جودة التنفيذ غير مرضية؛ `INCOMPLETE_WORK` العمل غير مكتمل؛ `UNAPPROVED_COST` تكلفة غير متفق عليها؛ `PROPERTY_DAMAGE` تلف في الممتلكات؛ `PAYMENT_ISSUE` مشكلة في الدفع أو المبلغ؛ `PROVIDER_CONDUCT` سلوك الفني؛ `OTHER` سبب آخر.
